## 問題 1 　ノードの索引づくりが空回りしていた

**症状。** 資料一覧が 0 件。資料のページは「見つかりません」。

**原因。** ノードと、その中のデータベースが同時に起動しました。
ノードは準備中のデータベースに問い合わせて失敗し、目録を入れる場所を作らずに先へ進んでいました。
そのため「どこまで読んだか」を保存できず、約 90 秒ごとに最初から読み直していました。

**対応。** ノードを再起動しました。再発防止に、データベースの準備を最大 2 分待ってから起動するようにしました。

**根の深さ。** Ocean Node 本体の不具合です。自分でノードを建てた人だけが出会う問題で、Clio-X 固有ではありません。

## 問題 2 　ポータルの問い合わせ方がノードと合っていなかった

**症状。** 目録ができても一覧は 0 件のまま。「compute」で絞り込むと必ず 0 件。

**原因。** Clio-X の画面は、Pontus-X が使っている旧来の目録サーバ（Aquarius）を前提に作られています。新しいノードは同じ形の問い合わせに空を返します。
回避の仕組みはありましたが、接続先が開発者の手元の PC のときしか働いていませんでした。

**対応。** 接続先がノードなら回避の仕組みが働くように直し、資料のサービス（1 件に複数ある）の中までたどれるようにしました。
絞り込みごとの件数が、ノードから直接数えた件数と一致しました（compute 4・download 9・datasets 4・algorithms 5）。

**根の深さ。** 今は隠れている問題です。Ocean Protocol は旧来の目録サーバを新しいノードに置き換える方向です。Pontus-X が置き換えた時点で、本家の Clio-X でも同じ「0 件」が起きるはずです。

## 問題 3 　以前登録した 29 件が、どれも目録に出なくなった

**症状。** 2026 年 8 月 10〜13 日に登録した試験用の資料 29 件が、目録に 1 件も出ない。

**原因。** 資料を登録すると、ノードが説明とファイルの所在を封印します。
台帳には、封印したものと一緒に、**封印したノードの住所**が残ります。
目録に資料を出すには、その住所に開封を頼む必要があり、ほかの手段はありません。
29 件の住所は、手元の PC（12 件）と、9 月 5 日に閉じたクラウドのサーバ（16 件）でした（1 件は住所の記録なし）。
どちらももう応答しません。クラウドのサーバの鍵は手元に残っていて、新しいノードも同じ鍵を使っています。それでも役に立ちませんでした。目録が頼みに行くのは鍵の持ち主ではなく、記録された住所だからです。

**対応。** 取り戻す作業はしていません。試験用なので、新しく登録するほうが早かったためです。

**根の深さ。** Ocean Protocol の設計そのものです。資料は、登録に使ったノードに結び付いたままになります。
長く残すことを仕事にするアーキビストにとって、機能の説明より先に知っておくべき性質です。

## 問題 3 への対策

| 種類                  | 内容                                                                                                                                                                      | 状態                 |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- |
| これから防ぐ          | 住所を機械の番号ではなく名前（`cliox-node.ldas.jp`）にする。名前なら新しい機械に向け直せる。ノードの鍵を保管する。この 2 つがそろえば、ノードを引っ越しても資料は消えない | 対応済み             |
| 取り戻す              | 資料の持ち主のウォレットは説明を書き換えられる。新しいノードで封印し直せば、識別子と履歴を保ったまま戻せる                                                                | 推定・未試行         |
| Clio-X の仕組みで防ぐ | **説明を封印しない登録**。目録はもともと公開するもの。封印するのはファイルの所在だけにする                                                                                | 試作に着手（中断中） |
| Clio-X の仕組みで防ぐ | 加盟の条件として、名前の住所と鍵の保管を機関に求める                                                                                                                      | 相談                 |
| Clio-X の仕組みで防ぐ | 機関のシステムを正本とし、Clio-X は公開の窓口と位置づける                                                                                                                 | 相談                 |
| Clio-X の仕組みで防ぐ | ノードを閉じるとき、資料を別の機関のノードへ移す決まりを作る                                                                                                              | 相談                 |
