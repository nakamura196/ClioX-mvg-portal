# Clio-X とデータスペースプロトコル（DSP）のコネクタ

**利用者から見ると、ds.ldas.jp と cliox.ldas.jp は並んだ 2 つの入口です。目的で選びます。写しを受け取らずにデータで計算するなら cliox.ldas.jp、契約して閲覧・ダウンロードするなら ds.ldas.jp です。**
裏で Ocean が動くか、データスペースプロトコル（DSP）が動くかは、利用者には見えません。
このページでは、2 つのポータルが同じ DSP の提供者にどうつながるか、そして Clio-X と並べて ds.ldas.jp を作る理由を説明します。

![3 つの列。左が利用者、中央が 2 つのポータル（ds.ldas.jp と cliox.ldas.jp）、右が DSP の提供者。ds.ldas.jp は依頼のたびに DSP で提供者とやり取りする。cliox.ldas.jp は DSP を話さず、Ocean ノードがジョブごとに Clio-X のデータの提供者のデータの面からファイルを取る。](/dsp/dsp-connector-ja.svg)

## それぞれの役目

- **DSP の提供者**は DSP を実装しています。
  カタログに ODRL（機械が読める利用条件）のポリシーを付けて載せ、契約を交渉し、転送でデータの場所と認証情報を渡します。
  提供者は 2 つの部分からなります。
  **制御の面**（カタログ・ポリシー・契約）と、**データの面**（データを取りに行く場所）です。
  - news-a と yanesen は `ldas-dsp` で作った提供者ノードで、2 つの面を 1 つに持っています。
  - **Clio-X のデータの提供者**は、2 つの面が分かれた 1 つの提供者です。
    データの面は `cliox-files.ldas.jp`（稼働中、Cloudflare Access が守る）です。
    制御の面 `cliox-dsp.ldas.jp` は `ldas-dsp` で作る予定で、まだ配備していません。
    データの面は交渉をしません。有効な認証情報を持つ相手にファイルを渡すだけです。
- **2 つのポータル**はカタログを見せ、人が操作する画面です。どちらもコネクタではありません。
  - **ds.ldas.jp** は DSP の提供者のカタログを集め、契約を結び、支払いを受けます（後述）。
  - **cliox.ldas.jp**（Clio-X ポータル、Ocean の上で動く）は、公開する人がデータセットを登録し、利用者が購入して計算ジョブを始める場所です。
- **Ocean ノード**はデータセットを持たず、DSP も話しません。
  URL とヘッダーでファイルを取り、アルゴリズムを動かし、結果を返します。
- **Clio-X の運営者**は、ノードのための契約を 1 回だけ結びます（後述）。

## ポータルが提供者に届く 2 つの道

図では矢印を分けています。

- **ds.ldas.jp: 依頼のたびに DSP**（藍色）。
  利用者が ds.ldas.jp で結ぶ契約は、1 件ずつ提供者の制御の面との DSP の交渉です。
- **cliox.ldas.jp: ジョブごとには DSP を使わない**（橙色）。
  ポータルと提供者のデータの面のあいだに Ocean ノードがいて、ジョブごとにファイルを取りに行きます。
  DSP を使うのは 1 回だけです。Clio-X の運営者がノードのための利用者側として、提供者の制御の面と長期の契約（「計算だけ、再配布はしない」）を結びます。
  そこで得た認証情報は、データセットを登録するときに DDO（資産の説明。暗号化して保存）に入れます。

その後の計算ジョブは次のように動きます。

1. 利用者が cliox.ldas.jp で資産を購入し、ジョブを始めます。
2. ノードが DDO の URL とヘッダー（Cloudflare Access のサービストークン）で、データの面からファイルを取ります。
3. ノードはネットワークのない隔離したコンテナでアルゴリズムを動かします。
4. ノードは結果だけを返します。利用者にファイルは渡りません。

## 人と提供者を直接結ぶ 2 本の線

左の列から提供者へ、直接の矢印が 2 本あります。この 2 本は別のものです。

1. **DSP のデータの受け渡し（利用者）。**
   ds.ldas.jp で契約すると、利用者は短期の通行証を受け取り、提供者のデータの面から直接データを取ります（news-a は 20 分）。
   データはポータルを通りません。
2. **Cloudflare Access のメールでのログイン（提供者の担当者）。**
   `cliox-files.ldas.jp` にログインしてファイルを確かめるのは、提供者自身の担当者だけです。今は運営者だけです。
   これは管理のためのもので、利用者の道ではありません。
   ノードのサービストークンも Cloudflare Access ですが、図ではジョブごとのファイルの矢印として描いています。

## ds.ldas.jp とは

ds.ldas.jp は、人文学・アーカイブの DSP の提供者のためのポータルとカタログです。

- 登録された提供者（news-a、yanesen、自前でノードを持てない機関の共同のノード）のデータセットを並べます。
- 利用者はデータセットの ODRL のポリシーのもとで契約します。契約は提供者との DSP の交渉です。
- 支払いは pay.ldas.jp を通した円建てです。pay.ldas.jp は銀行振込・カード・JPYC を 1 つの口で受ける作りです。利用者は財布もガス代も要りません。
- 契約の後、利用者は提供者のデータの面から直接、閲覧・ダウンロードします。

DSP の部分は公開のパッケージ `ldas-dsp`（`src/dsp-core/`）です。
Catena-X と同じく提供者ごとにノードを持ちます。今はすべてのノードを 1 人で動かしています。

## 身元: LDAS ID（id.ldas.jp が出す検証可能な証明書）

id.ldas.jp は、メールのドメイン・学認・ORCID を確かめたうえで、検証可能な証明書（VC）を出します。
ポータルは OpenID for Verifiable Presentations（OID4VP 1.0）でそれを求めます。
証明書は SD-JWT VC（`dc+sd-jwt`）です。本人はポータルが求めた項目だけを見せ、鍵の結び付けの JWT（`kb+jwt`）で、見せているのが持ち主本人であることを示します。
ポータルは発行者の署名と失効の一覧を確かめます。

2026 年 11 月 26 日に確かめた、それぞれのポータルでの使い道です。

|              | ds.ldas.jp                                                                                                                                        | cliox.ldas.jp                                                                                                                                                     |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ログイン     | すべての利用者が LDAS ID でログイン                                                                                                               | 見るだけならログイン不要。購入には財布が要る                                                                                                                      |
| VC の使い道  | 利用者が誰か、学術ドメイン（`*.ac.jp`）などの条件                                                                                                 | 提供者が「確認済み」の印を申し込むとき（`/experiment/apply-provider/`）と、チャットボットのログインが必須のとき（今は必須でない）                                 |
| 確かめたこと | DCQL で `dc+sd-jwt` を求める OID4VP（コード: `dataspace-mock` の `src/components/LdasLoginModal.tsx`、検証は `ldas-dsp` の `src/dsp-core/vc.ts`） | `GET /api/auth/ldas/start` が `response_type=vp_token` と `dc+sd-jwt` を求める DCQL を付けて `id.ldas.jp/authorize` に転送する（11 月 26 日にリクエストして確認） |

つまり、2 つのポータルは同じ証明書を受け取りますが、ログインに使うのは ds.ldas.jp だけです。
cliox.ldas.jp で購入を可能にしているのは財布です。
ポータルは `/api/policy-server`（Ocean ノードが呼べる検証の窓口）にも応答します。こちらのノードがそれを呼ぶ設定になっているかは確かめていません。今後は Pontus-X の標準（Ocean の policy-server と walt.id）を使う予定です。

## 3 つの層: 仕組み・場・入口

どのデータスペースにも、同じ 3 つの層があります。

| 層                         | Pontus-X                                | Catena-X（自動車）                                                                                      | こちら                                                          |
| -------------------------- | --------------------------------------- | ------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 仕組み（ソフトと取り決め） | Ocean Protocol。チェーン（Oasis）を使う | DSP と公式の実装 Tractus-X EDC。チェーンなし                                                            | DSP を `ldas-dsp` で実装。チェーンなし                          |
| 場（ネットワークと運営者） | Pontus-X。deltaDAO たちが運用           | Catena-X。協会が規格を決め、運営会社（Cofinity-X など）が共通の部品を動かし、各社が自分のコネクタを持つ | ds.ldas.jp。提供者ごとにノード（news-a・yanesen・共同のノード） |
| 入口（ポータル）           | Clio-X ほか。アーカイブ・文化遺産向け   | 用途ごとのアプリ                                                                                        | ds.ldas.jp の画面                                               |

Pontus-X と Eclipse は同じ層ではありません。Eclipse の DSP と EDC に当たるのは Ocean Protocol です。
ds.ldas.jp は、仕組みと「提供者ごとにノードを持つ」形が Catena-X と同じです。違うのはノードを誰が動かすかです。
Catena-X の欄は、協会の規格（CX-0018・運営モデル）と Cofinity-X の案内を 2026 年 11 月 25 日に検索で確かめたもので、細部は確かめていません。

## Clio-X と並べて ds.ldas.jp を作る理由

::: warning 理由の候補（確認待ち）
以下は候補です。まだ合意していません。
:::

1. **EU のデータスペースとつながる。** ds.ldas.jp は、Gaia-X・Catena-X・Eclipse EDC の取り決めである DSP を実装しています。Clio-X は DSP を話さない Ocean の上で動きます。
2. **財布もガス代も要らない。** 利用者は pay.ldas.jp で円で払います。cliox.ldas.jp での購入には財布が要ります。
3. **計算だけでなく、閲覧・ダウンロードにも。** 契約のもとで貸し出せるデータもあります。Clio-X は写しを渡さない計算のためのものです。
4. **Clio-X を補う。** 上の Clio-X のデータの提供者のように、DSP の提供者のデータの面を、Clio-X が計算に使う保管場所にできます。

## Ocean の部分と、こちらの部分

Ocean そのものは、URL とヘッダーでファイルを取るだけです。
データの前に DSP の契約を置くのはこちらの設計で、Ocean の機能ではありません。
ds.ldas.jp と `ldas-dsp` の提供者は DSP を実装しています。
DSP の適合試験（TCK）は走らせていないので、「適合している」とは言いません。

## 今の状態

- 稼働中: news-a・yanesen の提供者を持つ ds.ldas.jp。Cloudflare Access が守る Clio-X のデータの面 `cliox-files.ldas.jp`。そこからサービストークンでファイルを取るノード（実際の計算ジョブがこの形でファイルを取り、処理した）。ds.ldas.jp の LDAS ID のログインと、cliox.ldas.jp の「確認済み」の申し込み。
- 計画中: Clio-X のデータの提供者の制御の面（`cliox-dsp.ldas.jp`、`ldas-dsp` で作る）と、ノードのための 1 回の契約。
