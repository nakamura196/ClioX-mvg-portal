# Clio-X とデータスペースプロトコル（DSP）のコネクタ

**Clio-X（Ocean の compute-to-data）と DSP のコネクタは役目が違い、1 つの認証情報でつなげられます。**
コネクタは、誰がどんな条件でデータセットを使えるかを決めます。
Ocean ノードは、ファイルを利用者に渡さずに計算だけを行います。
このページは、公開できないデータを持つ提供者を想定して、両者の関係を一般的な形で図にしたものです。

![Clio-X、Ocean ノード、DSP コネクタの関係。ファイルが動く道と、メタデータや結果だけが動く道](/dsp/dsp-connector-ja.svg)

## それぞれの役目

- **Ocean ノードはデータセットを持ちません。**
  資産の説明（DDO）に、ファイルの URL とリクエストのヘッダーが暗号化されて入っています。
  計算のジョブごとに、ノードがファイルを取りに行きます。
  隔離したコンテナ（ネットワークなし）でアルゴリズムを動かし、結果だけを返します。
  利用者がファイルを受け取ることはありません。
- **データは、提供者が運営する非公開の場所に置いたままです。**
  実際に動かしている例が `cliox-files.ldas.jp` で、Cloudflare Access の内側にあります。
  人はメールでログインします。
  ノードは、長期間有効なサービストークン（ヘッダー 2 つ）を使います。トークンは DDO に暗号化して入っています。
- **DSP のコネクタ**（例: ds.ldas.jp、Eclipse EDC）は、カタログにデータセットを載せ、ODRL（機械が読める利用条件）のポリシーを付けます。
  利用者と契約を結んだあと、転送を始めます。転送の結果として、データの場所と一時的な認証情報が渡されます。

## 両者のつなぎ方

Clio-X では、Ocean ノードをコネクタの**利用者の 1 つ**として扱います。
この利用者は、「計算だけ、再配布はしない」という長期の合意を持ちます。
ふつうは、合意のあとの転送で一時的な認証情報が出ます。
ここでは認証情報を期限のないものにして、DDO に入れます。ノードはジョブのたびにそれを読みます。

## Ocean の機能と、私たちの設計

Ocean 自体は、URL とヘッダーでファイルを取りに行くだけです。
DSP は話しません。
データの前に DSP のコネクタを置くのは、私たちの設計で、Ocean の機能ではありません。

ds.ldas.jp は DSP を実装しています。ただし DSP の適合性テスト（TCK）は実行していないので、「適合している」とは書きません。
コネクタの一例であり、唯一の選択肢ではありません。
