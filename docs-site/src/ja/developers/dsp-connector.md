# Clio-X とデータスペースプロトコル（DSP）のコネクタ

**Clio-X（Ocean の compute-to-data）は DSP を話しません。DSP の契約は最初に 1 回だけ結び、そこで得た認証情報をデータセットの説明に入れます。**
そのあとの計算ジョブは Ocean だけで動きます。ノードがファイルを取りに行き、アルゴリズムを動かし、結果を返します。
このページは、公開できないデータを持つ提供者を想定して、両者の関係を一般的な形で図にしたものです。

## それぞれの役目

- **DSP の提供者**は DSP を話します。
  カタログに ODRL（機械が読める利用条件）のポリシーを付けて載せ、契約を交渉し、転送でデータの場所と認証情報を渡します。
  例: news-a と yanesen（`ldas-dsp` で作った提供者ノード）、Eclipse EDC。
  Clio-X のデータ用の提供者は、`ldas-dsp` で作る予定です。
- **データの保管場所**は DSP を話しません。
  ファイルを置いて渡すだけです。
  例は `cliox-files.ldas.jp` で、Cloudflare Access が守っています。人はメールでログインし、Ocean ノードは長期間有効なサービストークン（ヘッダー 2 つ）を使います。
  ファイルを守っているのは Cloudflare Access で、コネクタではありません。
- **ポータル**はカタログを見せ、利用者が操作する画面です。コネクタではありません。
  ds.ldas.jp は提供者のカタログを集め、利用者が契約できるようにします。
  Clio-X ポータル（cliox.ldas.jp）では、公開する人がデータセットを登録し、利用者が購入します。
- **Ocean ノード**はデータセットを持たず、DSP も話しません。
  URL とヘッダーでファイルを取りに行くだけです。

## 最初に 1 回: 契約

DSP の契約は、提供者と **Clio-X の運営者**の間で 1 回だけ結びます。運営者は、ノードのための利用者側として動きます。
合意は長期のもので、「計算だけ、再配布はしない」という内容です。
そこで得た長期の認証情報は、公開する人が Clio-X ポータルでデータセットを登録するときに、DDO（資産の説明。暗号化して保存）に入れます。

## 計算ジョブごと: DSP は使わない

1. 利用者が Clio-X ポータルで資産を購入し、ジョブを始めます。
2. ノードが、DDO にある URL とヘッダーで、保管場所からファイルを取得します。
3. ノードが、隔離したコンテナ（ネットワークなし）でアルゴリズムを動かします。
4. ノードは結果だけを返します。

利用者がファイルを受け取ることはありません。
契約とジョブは時間が離れています。契約はジョブのたびにやり直しません。

## Ocean の機能と、私たちの設計

Ocean 自体は、URL とヘッダーでファイルを取りに行くだけです。
データの前に DSP の契約を置くのは、私たちの設計で、Ocean の機能ではありません。
ds.ldas.jp と `ldas-dsp` の提供者は DSP を実装しています。ただし DSP の適合性テスト（TCK）は実行していないので、「適合している」とは書きません。
