# どこに何が記録されるか（チェーンの上と外）

Clio-X に資料を登録すると、記録は 2 か所に分かれて残ります。
ひとつはブロックチェーン（ここでは Sepolia）の上です。これを**オンチェーン**と呼びます。
もうひとつはチェーンの外のサーバで、**オフチェーン**と呼びます。

先に結論を書きます。
チェーンに載るのは「誰が、いつ、何を登録し、誰が使ったか」の記録と、資料の目録にあたる情報です。
**資料の本文や画像そのものは、チェーンには載りません。**

## チェーンの上にあるもの

チェーンに書いたものは、誰でも読めます。そして消せません。
直したいときは、新しい記録を上から重ねます。古い記録は履歴として残ります。

- **登録証**（data NFT）と、その持ち主のウォレットのアドレス。資料ごとに 1 つ作られます
- **利用券**（datatoken）と、無料か有料かの設定
- **目録カード**（DDO）。題名、説明、作成者、ライセンス、提供サーバの住所などが入ります。
  暗号化して載せることも、そのまま載せることもできます
- **目録カードの指紋**（ハッシュ）。カードが後から書き換えられていないことを確かめられます
- **目録カードを開ける Node の住所**。暗号化したカードは、登録に使った Node にしか開けません
- **利用の記録**。誰が、いつ利用券を使ったか
- **利用を許す相手の名簿**。機関どうしで名簿を共有する仕組みを使う場合です

## チェーンの外にあるもの

- **資料の本文・画像**。機関のサーバや、IPFS・Arweave のようなファイルの置き場所にあります。
  目録カードには置き場所が書かれています。ただし、ふつうは暗号化されていて、Node にしか読めません
- **Node の鍵**。Node のサーバの中にあります。
  これを失うと、暗号化した目録カードもファイルの置き場所も、開けなくなります
  （[登録に使ったサービスが無くなったとき](./when-a-node-closes)）
- **検索用の索引**。Node がチェーンを読んで作った写しです。消えても、チェーンから作り直せます
- **計算の実行と結果**。Node の上で行われます。チェーンに残るのは「利用した」という記録だけです
- **ポータル（画面）**。上の記録を読んで表示しているだけで、記録の正本は持っていません

IPFS は名前が似ていますが、ブロックチェーンではありません。
ファイルの中身から住所を決める、ファイルの置き場所の仕組みです。
誰も保管しなくなれば、ファイルは取り出せなくなります。

## 実例: 校異源氏物語

試用サイトには「校異源氏物語」の各帖（54 件）が並んでいます。
これは、Ocean の仕組みのうちチェーンの部分だけを使って登録した実験です。

- 目録カードは**暗号化せずに**チェーンに載せています。
  たとえば「てならひ（第 53 帖）」のカードは、2026 年 8 月 27 日の取引
  [0x17a6…0840](https://sepolia.etherscan.io/tx/0x17a60b8e1086d707734d077edc62d6d7eb3dbf884f3d3e38dae73b9527670840)
  の中身として、全文が読めます
- 提供サーバの欄には、サーバではなく本文の IPFS の住所（`ipfs://…`）を書いています
- 本文は IPFS にあり、Filebase という保管サービスが保管しています

このため、チェーンの記録だけを読めば、Node がなくても誰でも本文にたどり着けます。
その代わり、ポータルからはダウンロードも計算もできません。
ポータルは提供サーバ（Node）を通して配ることを前提にしているからです。
ポータルの資料ページには、そのことと本文へのリンクを表示しています。

## アーキビストとして気をつけたいこと

- **目録カードを暗号化せずに載せる場合、個人情報や非公開の情報を書かないでください。**
  チェーンに一度書いたものは、消せません
- 暗号化して載せる場合は、**Node の鍵を失わないこと**が、資料を読み続けるための条件になります
- 本文の置き場所は、チェーンとは別に保管の手当てが要ります。チェーンは中身を保管しません
