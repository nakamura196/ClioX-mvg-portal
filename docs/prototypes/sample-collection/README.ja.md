# 試作 (h): 分析を試せる見本の資料

ブランチ `proto/sample-collection`。一言でいうと、国立国会図書館のパブリックドメインの画像 8 枚を使い、ウォレットを持たない人でも分析を最初から最後まで試せるページです。
ページを選び、分析を選び、動かし、戻ってくるのは結果のファイルだけで、画像は保管者の手元に残ることを確かめられます。

- URL: `/sample-collection`（日本語: `/ja/sample-collection`）。メニューからはつないでいません。
- 資料: 歳旦発句牒（芭蕉 編、1682）、NDL info:ndljp/pid/2534020、PDM（パブリックドメイン）の表示あり。IIIF マニフェストの 8 コマすべてを幅 1600 px に縮めたものを `public/sample-collection/saitan/` に置いています。書誌の値はマニフェストから `collection.json` にそのまま写しています（訳していません）。コマの注記（「表紙」「本文」）はこちらで付けたもので、そう分かる印を付けています。
- 分析は 2 つで、それぞれどう動くかの印を付けています。
  - **固定性の確認 — ここで、いま動きます。** ファイルごとに SHA-256 と画素数をブラウザの中で計算し、CSV で書き出せます。それぞれのチェックサムを OCR の実行で記録したチェックサムと比べます（「OCR が読んだのと同じファイルか」）。`shasum -a 256` の結果と一致することを確かめました。
  - **文字の認識（NDL 古典籍 OCR-Lite）— 記録した実行を再生します。** 2026-09-26 に作成者の Mac で 1 回動かしました。Ocean Node の計算ジョブと同じコンテナ、同じ制限の下です（ネットワーク無し、2 CPU、2 GB、uid 1000、書き込めるのは `/data/outputs` だけ）。記録は `public/sample-collection/saitan-ocr-run/` にあります（`run.json` = コンテナのダイジェスト、コマンド、入力のチェックサム。`logs.txt` = ログそのまま。`outputs/` = ページごとの txt / TEI / NDL XML / JSON）。ログは手を加えずに見せ、選んだページの行を強調します。
- 結果の表示: `/data/outputs` のファイルと、「戻ってこなかったもの」（画像）を並べます。OCR の表示では、行を指すとページ上のその枠が強調されます。
- わざと残した正直な部分: 8 コマ目（裏表紙、文字なし）は OCR のプログラムの中で失敗しました（行が 0 のときの ZeroDivisionError）。「8 コマ目は失敗しましたが、ジョブは最後まで終わりました」と表示します。「下書きとして読んでください」の注記では、この実行で実際に起きた誤りを 2 つ示します（歳旦 → 歳且、物差しを「1.3.3」と読んだ）。
- 5 節では、実際のネットワークで何が変わるか（カタログ、ウォレット、ノード、時間）と何が変わらないかを並べ、テストネットワークでの試用はまだ開いていないと書いています。

分かっている限界: OCR はブラウザの中では動かせません（モデルが約 79 MiB、2 CPU で 8 ページに約 70 秒）。そのため再生であり、ページにもそう書いています。
スマートフォンではヘッダーがサイトのどのページでも 8 px はみ出します（既存のメニューの問題で、このページのものではありません）。

選ばれた場合の次の一手: 同じ 8 枚の画像と OCR のアルゴリズムを、mdx-clio のノードから Sepolia に計算用の資料として登録します。そうすれば「実際のネットワーク」の節からリンクできます（公開の試用になるので Vicki さんの了承が必要です）。
