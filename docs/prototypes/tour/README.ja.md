# 試作 (b): はじめての案内ツアー

ブランチ `proto/tour`。一言でいうと、はじめて来た人を 1 つの作業の最初から最後まで案内する、12 段・約 5 分のツアーです。
その作業とは、InterPARES のアーカイブズのデータセットを見つけ、記録を外に出さずに分析がそこへ届く様子を見ることです。
案内中は画面を暗くし、クリックを止めます。うっかり何かが起きることはありません。

- 最初の訪問で自動的に開きます。ヘッダーの「ガイド」（?）で開き直せます。止めたところから続きます。進み具合はブラウザの中にだけ残ります。
- 流れ: ようこそ → カタログ → 検索窓 → データセットのページ（題名と説明、保管者、識別子）→ 計算の欄（記録は動かない、計算する部屋、承認済みのアルゴリズム、ウォレットが要るただ 1 つの場面）→ ウォレットの接続 → おわり（InterPARES Trust AI の用語集へのリンク）。
- 各段でその画面をアーカイブズの言葉で説明します。3 つの段には緑色の「安全ですか？」の注記があります。日英あり。スマートフォンでは下からせり上がる表示になります。
- 文章: `content/firstRunTour.json` / `.ja.json`。コード: `src/components/FirstRunTour/`。ハイライトする場所は、既存の 7 つの部品に足した `data-tour` 属性で指定しています（ビルドごとに変わるクラス名には頼っていません）。
- 見本のデータセット: `did:op:65e78d53…f43d`（Pontus-X の開発用ネットワーク）。これが消えた場合は「まだ表示できません」のカードと「スキップ」を出します。

分かっている限界: 検索の段は検索窓を指し示すだけです。自前のメタデータサーバを建て直すまで、カタログの検索は何も返しません（公開されている Pontus-X のキャッシュは、このフォークが送る問い合わせに 405 を返します）。
計算の欄の 3 か所を指すために CSS の `:has()` を使っています（現行のブラウザはすべて対応）。

画面: `welcome-ja.png`、`record-en.png`、`access-ja.png`、`wallet-step-ja.png`、`phone-environment-ja.png`。
