# 試作: 1 件ごとの電力と水を見せると、選び方は変わるか

ブランチ `proto/sustainability-exp`（`deploy/hosting` の 80ae898b から）。共著論文（Lemieux / Laatikainen / 中村、Computational Archival Science、締切 2026-11-01）のための試作です。3 つあります。計算方法、2 条件の実験ページ、処理の受領証です。

## URL

- `/experiment`、`/ja/experiment`: 実験です。条件は最初の表示でランダムに決まり、`sessionStorage` に残ります。`?condition=control|treatment` で指定できます。`?pid=<コード>` も使えます。画面に条件の名前は出ません。
  - 対照: 1 件あたりの費用、所在地、法域、先住民データへの適合、認証を見せます。
  - 処理: 上に加えて、1 件あたりの電力・水・炭素を、区分つきで見せます。
  - 課題は 6 件、事業者は各 4 つです（順番は課題ごとにシャッフルし、記録します）。最後に結果を JSON と CSV で保存します。サーバーも通信もありません。
- `/experiment?view=design`: 全課題の計算結果と「最小」の印を並べます。「design.json を保存」で MATLAB のシミュレーション用に書き出せます。参加者の画面からはリンクしていません（対照の人に処理の数値が見えてしまうため）。
- `/experiment?view=receipt`: 受領証の見本です（形式 `clio-x-transaction-receipt/0.2`）。ハッシュ 2 つ、署名なしの JSON と元データの保存、「事業者として署名する」ボタン、「署名付き受領証を確かめる」欄があります。署名は「だれが出したか、書き換えられていないか」を示すだけで、事業者のセンサーが正しいことは示さない、と画面に書いています。下の「受領証のハッシュと署名」を見てください。

## 計算方法（`src/@utils/transactionFootprint.ts`、テスト 19 件）

IT 電力量 E = Σ P·Δt·s。電力が IT のみなら、施設電力量 = E × PUE。水は 2 通りです。流量なら Σ Q·Δt·r（r は既定で s。「計算シェアで割り振った会計上の推定で、実測の消費量ではない」と表示）。WUE なら IT 電力量 × WUE。炭素は、施設電力量 × 系統排出係数（location-based）です。Vicki さんの計算例（90 秒、25%、4 kW、12 L/h）は、0.025 kWh と 0.075 L にぴったり一致します（テストあり）。入力が欠けた値は「算出不可」と理由を出し、0 にはしません。割り当ての根拠は `dedicated`、`reserved-share`、`measured-per-job` です。割り振った値を「実測」とは表示しません。受領証には、区間、シェア、根拠、方法のバージョン、値ごとの区分、元データの参照が入ります。既存の `computeFootprint` のコードとテストは変えていません。

## 課題の設計（`content/experiment/trials.json`。コードを触らずに直せます）

「正解」は、1 件あたりの施設電力量が最小の選択肢です（同値は全部正解）。水が最小のもの、炭素が最小のものも同じ規則で計算して記録します。電力最小と水最小が一致したかも、課題ごとに記録します（水の数値がない選択肢があるときは null）。テスト（`src/@utils/experiment.test.ts`）で次を保証しています。電力最小が最安なのは多くて 1 課題。電力最小の所在地は 3 か所以上に分かれる。一致、不一致、水が不明の課題がそれぞれある。

処理条件で 6 課題を最後まで操作しました。保存した JSON と CSV は 6 行で、上の項目が入っています。（受領証のハッシュは、下の正規化 JSON 方式に置き換えました。）課題 4 では、水の数値がない選択肢に「算出不可」と理由が出ます。

## 相談したいこと

- 水の定義: 取水か消費か再循環の流量か、現地か発電由来か。受領証には記録します。デモの値は「消費・現地」としています。再循環の流量には警告を出します。
- 草稿の式は流量（L/h）で、図は年間平均の WUE（0.36 L/kWh）です。両方に対応しました。WUE の値は平均で、このジョブ自身の使用量ではありません。
- 炭素は草稿に定義がありません。ここでは、施設電力量 × location-based の系統排出係数としました。
- 事業者の数値はすべて例示です。本番には出典の取り決めが要ります。
- 参加者の画面（`?view=` の無い `/experiment`）では、ポータルのヘッダー・お知らせ・フッター・初回ツアーを出しません。参加者には課題だけが見えます。研究者向けの `?view=design` と `?view=receipt` は通常の枠のままです。参加者の画面には言語の切り替えが無いので、日本語は `/ja/experiment` を案内します。
- 条件名は、保存する結果ファイルには入ります（分析に必要）。画面には出ません。
- 反応時間は、表示から確定ボタンまでです。最初の選択までの時間も記録します。
- 受領証の署名と元データのハッシュは実装しました（下記）。未了は Sepolia へのスキーマ登録です。

## 受領証のハッシュと署名（2026-10-09）

コード: `src/@utils/canonicalJson.ts`、`src/@utils/receiptAttestation.ts`（テスト付き）、`src/components/Experiment/Sign.tsx`、`Verify.tsx`。依存は増やしていません。

- 正規化: RFC 8785（JCS）。キーを UTF-16 コード単位で並べ、空白なし、数値は ECMAScript の表記、NaN と Infinity は拒否、値のないキーは捨てます。
- `source.sha256` は、元データを正規化した JSON の SHA-256 です。元データ（`sample-source.json`）には、処理 ID、事業者、場所、時刻と、計算の入力（区間、電力、シェア、PUE、水の流量か WUE、系統排出係数）がすべて入っています。このファイルがあれば、誰でも同じ値を計算し直せます。Vicki の計算例（90 秒、25%、4 kW、12 L/h）の値をテストに固定しました（`4eeceaab…d598b`）。別実装（Python）でも同じ値になることを確かめました。
- 受領証のハッシュは、受領証を正規化した JSON の SHA-256 です。ファイルの整形を変えても変わりません。受領証の中の署名欄はなくしました。署名は別のファイル（署名付き受領証 `clio-x-signed-receipt/0.1`。受領証と EAS の off-chain attestation を一緒にしたもの。形は eas-sdk の出力と同じ）に入ります。
- 署名: EAS の off-chain attestation（EIP-712。ガス代なし。何も送りません）。Sepolia の EAS `0xC2679fBD37d54388Ce493F1DB75320D236e1815e`、chainId 11155111、コントラクトの `VERSION()` は "0.26"（2026-10-09 に Sepolia で確認）。ドメイン名は "EAS Attestation"、off-chain の版は 2（salt 付き）。ethers v5 だけで実装し、検証にウォレットは要りません。
- スキーマ: `bytes32 receiptSha256,bytes32 sourceSha256,string method`（revocable、resolver なし）。UID は `0xcc83b871…2e21d`。載せるのは 2 つのハッシュと方法の名前だけです。受領証の本文は載せません。数値は受領証側に残り、公開せずに済みます。それでも、元データと会計方法の版は署名に結びつきます。
- 署名者（attester）は、事業者が接続したウォレットです。受取人（recipient）は、依頼した人のウォレットで、画面に入力します（チェックサムを確認）。
- 突き合わせ: `@ethereum-attestation-service/eas-sdk` 2.10.0（ethers v6）で作った署名を、固定の値として `src/@utils/__fixtures__/` に置きました（公開のテスト用ニーモニック、時刻と salt は固定）。ethers v5 の実装は、署名、UID、データの符号化、easscan 用の圧縮パッケージのすべてで同じ値を出しました（テスト「cross-check」）。
- 確かめる欄: 受領証のハッシュを計算し直し、署名された値と比べ、署名者を復元し、署名者・受取人・時刻を出します。方法、スキーマ、UID、ネットワークも確認します。元データのファイルを選ぶと、そのハッシュも比べます。
- easscan: sdk のリンクの形は `https://sepolia.easscan.org/offchain/url/#attestation=<圧縮して base64 にした値>` です。画面でこのリンクを作ります（ブラウザの CompressionStream）。圧縮前のパッケージは sdk と一致しています。リンクを easscan で実際に開く確認は、まだしていません。
- `sample-signed-receipt.json` は公開のテスト用の鍵で署名しています（ファイルにも書いてあります）。実在の事業者ではありません。

未了: スキーマは Sepolia に登録していません（利用者の作業です。SchemaRegistry は `0x0a7E2Ff54e76B8E6659aedc9103FB21c038050D0`。登録するまで easscan にスキーマ名が出ないことがあります）。実際のウォレットでの署名は、ブラウザで試していません（テスト用ブラウザにウォレットがないため）。署名の関数そのものは、ウォレット相当のオブジェクトでテスト済みです。MetaMask は Sepolia にする必要があります（画面が切り替えを頼みます）。revocable にするか、attestation をチェーンにも載せるかは、決まっていません。
