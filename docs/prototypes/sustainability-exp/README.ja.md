# 試作: 1 件ごとの電力と水を見せると、選び方は変わるか

ブランチ `proto/sustainability-exp`（`deploy/hosting` の 80ae898b から）。共著論文（Lemieux / Laatikainen / 中村、Computational Archival Science、締切 2026-11-01）のための試作です。3 つあります。計算方法、2 条件の実験ページ、処理の受領証です。

## URL

- `/experiment`、`/ja/experiment`: 実験です。条件は最初の表示でランダムに決まり、`sessionStorage` に残ります。`?condition=control|treatment` で指定できます。`?pid=<コード>` も使えます。画面に条件の名前は出ません。
  - 対照: 1 件あたりの費用、所在地、法域、先住民データへの適合、認証を見せます。
  - 処理: 上に加えて、1 件あたりの電力・水・炭素を、区分つきで見せます。
  - 課題は 6 件、事業者は各 4 つです（順番は課題ごとにシャッフルし、記録します）。最後に結果を JSON と CSV で保存します。サーバーも通信もありません。
- `/experiment?view=design`: 全課題の計算結果と「最小」の印を並べます。「design.json を保存」で MATLAB のシミュレーション用に書き出せます。参加者の画面からはリンクしていません（対照の人に処理の数値が見えてしまうため）。
- `/experiment?view=receipt`: 受領証の見本です。SHA-256 と JSON の保存ができます。ハッシュは「ファイルが書き換えられていない」ことを示すだけで、事業者のセンサーが正しいことは示さない、と画面に書いています。署名は未実装です。

## 計算方法（`src/@utils/transactionFootprint.ts`、テスト 19 件）

IT 電力量 E = Σ P·Δt·s。電力が IT のみなら、施設電力量 = E × PUE。水は 2 通りです。流量なら Σ Q·Δt·r（r は既定で s。「計算シェアで割り振った会計上の推定で、実測の消費量ではない」と表示）。WUE なら IT 電力量 × WUE。炭素は、施設電力量 × 系統排出係数（location-based）です。Vicki さんの計算例（90 秒、25%、4 kW、12 L/h）は、0.025 kWh と 0.075 L にぴったり一致します（テストあり）。入力が欠けた値は「算出不可」と理由を出し、0 にはしません。割り当ての根拠は `dedicated`、`reserved-share`、`measured-per-job` です。割り振った値を「実測」とは表示しません。受領証には、区間、シェア、根拠、方法のバージョン、値ごとの区分、元データの参照が入ります。既存の `computeFootprint` のコードとテストは変えていません。

## 課題の設計（`content/experiment/trials.json`。コードを触らずに直せます）

「正解」は、1 件あたりの施設電力量が最小の選択肢です（同値は全部正解）。水が最小のもの、炭素が最小のものも同じ規則で計算して記録します。電力最小と水最小が一致したかも、課題ごとに記録します（水の数値がない選択肢があるときは null）。テスト（`src/@utils/experiment.test.ts`）で次を保証しています。電力最小が最安なのは多くて 1 課題。電力最小の所在地は 3 か所以上に分かれる。一致、不一致、水が不明の課題がそれぞれある。

| 課題                                | 最安       | 電力最小             | 水最小                                         | 炭素最小       |
| ----------------------------------- | ---------- | -------------------- | ---------------------------------------------- | -------------- |
| t1 文字認識（共有 GPU）             | カルガリー | 東京                 | ストックホルム（不一致）                       | ストックホルム |
| t2 学習（専有）                     | 東京       | オレゴン             | オレゴン                                       | ストックホルム |
| t3 文字起こし                       | カルガリー | カルガリー           | カルガリー                                     | ストックホルム |
| t4 埋め込み                         | オレゴン   | モントリオール       | ストックホルム（モントリオールは水の数値なし） | ストックホルム |

数値はすべて例示です（画面に「デモ用のデータ」と出します）。系統排出係数は既存の登録表から取り、PUE・WUE・電力・費用は仮の値です。

## 確かめたこと（2026-10-09、開発サーバーと Playwright）

処理条件で 6 課題を最後まで操作しました。保存した JSON と CSV は 6 行で、上の項目が入っています。受領証の画面のハッシュは、保存したファイルの sha256 と一致しました（`b072c348…ad13e7`）。課題 4 では、水の数値がない選択肢に「算出不可」と理由が出ます。

## 相談したいこと

- 水の定義: 取水か消費か再循環の流量か、現地か発電由来か。受領証には記録します。デモの値は「消費・現地」としています。再循環の流量には警告を出します。
- 草稿の式は流量（L/h）で、図は年間平均の WUE（0.36 L/kWh）です。両方に対応しました。WUE の値は平均で、このジョブ自身の使用量ではありません。
- 炭素は草稿に定義がありません。ここでは、施設電力量 × location-based の系統排出係数としました。
- 事業者の数値はすべて例示です。本番には出典の取り決めが要ります。
- 参加者の画面（`?view=` の無い `/experiment`）では、ポータルのヘッダー・お知らせ・フッター・初回ツアーを出しません。参加者には課題だけが見えます。研究者向けの `?view=design` と `?view=receipt` は通常の枠のままです。参加者の画面には言語の切り替えが無いので、日本語は `/ja/experiment` を案内します。
- 条件名は、保存する結果ファイルには入ります（分析に必要）。画面には出ません。
- 反応時間は、表示から確定ボタンまでです。最初の選択までの時間も記録します。
- 受領証の署名と、元データの本物のハッシュは未実装です。
